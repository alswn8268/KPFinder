# K-PathFinder

![tests](https://github.com/alswn8268/KPFinder/actions/workflows/tests.yml/badge.svg)

> **AI 폴더 정리 도우미** — 2026년 사내 AX 과제 해결 공모전 출품작. 어질러진 업무 폴더를 스캔해서
> 조직 표준 규칙과 로컬 AI가 더 깔끔한 폴더 구조를 **제안**하는 로컬 실행 도구입니다.
> **AI는 절대 자동으로 파일을 옮기지 않습니다.** 항상 **환경 점검 → 스캔 → 규칙/AI 제안 →
> 사람이 파일별로 확인·수정 → 적용** 순서를 따릅니다.

## 핵심 원칙

- 완전 로컬 실행: 인터넷 연결 없이 [Ollama](https://ollama.com) 로컬 LLM(`exaone3.5:2.4b`)만 사용합니다.
  외부 API 호출이 전혀 없어 민감한 사내 문서가 외부로 나가지 않습니다.
- **미리보기 우선**: '적용' 버튼을 누르기 전까지 원본 폴더의 어떤 파일도 이동·수정·삭제되지 않습니다.
- **경로 보호**: 목적지가 대상 폴더를 벗어나거나(`..`, 절대경로, 심볼릭 링크 탈출), 운영체제 예약어/금지문자를
  포함하면 적용 자체가 차단됩니다.
- **트랜잭션 이동**: 이동 계획은 이동 시작 전에 먼저 저장되고, 파일마다 즉시 로그가 남으며, 중간에
  실패하면 이미 옮긴 파일까지 자동으로 원상복구됩니다.
- **사람이 최종 결정**: AI/규칙 제안을 파일별로 검토·수정·제외할 수 있고, 조직 표준 폴더 템플릿을
  벗어난 임의의 카테고리는 만들어지지 않습니다.
- **되돌리기 가능**: 실제로 파일을 이동하면 버전으로 기록되고, 더 최근 버전부터 순서대로 되돌릴 수 있습니다.
- **AI 없이도 동작**: Ollama가 꺼져 있어도 스캔·중복 탐지·검색·조직 규칙 기반 1차 분류·적용까지
  핵심 기능을 계속 사용할 수 있습니다.

## 준비물

> 회사·공공기관 PC처럼 인터넷·관리자 권한·망분리 등이 제한된 환경이라면
> [회사_공공기관_PC_설치_가이드.md](./회사_공공기관_PC_설치_가이드.md)에서 환경별(인터넷 유무 ×
> 관리자 권한 유무 × 망분리 여부) 설치 경로를 먼저 확인하세요.

1. Python 3.10 이상
2. [Ollama](https://ollama.com) 설치 후 모델 다운로드 (최초 1회, 약 1.6GB) — **선택 사항**입니다.
   Ollama 없이도 조직 규칙 기반 분류로 핵심 기능을 쓸 수 있습니다.

   ```bash
   ollama pull exaone3.5:2.4b
   ollama serve   # 이미 실행 중이면 생략 가능
   ```

3. 파이썬 패키지 설치

   ```bash
   pip install -r requirements.txt
   ```

## 실행

두 가지 UI 중 하나를 고를 수 있습니다. 기능은 동일하고, 백엔드 로직(`app/*.py`)도 그대로 공유합니다.

### 방법 A. 웹 UI (FastAPI + Vue, 권장)

```bash
# 1) API 서버
uvicorn api.main:app --reload --port 8000

# 2) 프런트엔드 (다른 터미널에서)
cd frontend
npm install
npm run dev   # http://localhost:5173
```

빌드해서 API 서버 하나로만 서빙하려면 `cd frontend && npm run build` 후 다시
`uvicorn api.main:app --port 8000`을 실행하면 `frontend/dist`를 자동으로 함께 서빙합니다.

### 방법 B. Streamlit (폴백)

```bash
streamlit run streamlit_app.py
```

두 UI 모두 다음 흐름을 따릅니다(아래 설명은 Streamlit 기준 탭/사이드바 이름이며, 웹 UI는 좌측
내비게이션의 같은 이름 메뉴에 대응합니다):

1. 사이드바의 **🩺 실행 환경 점검**에서 Ollama 연결, 모델 설치 여부, 폴더 권한, 저장 공간 등을
   확인합니다. Ollama 관련 항목이 오류여도 나머지 기능은 계속 쓸 수 있습니다.
2. **🗂️ 조직 표준 템플릿**에서 기본 템플릿을 그대로 쓰거나, 템플릿 JSON을 가져오거나, 현재 폴더
   구조로 새 템플릿을 만듭니다.
3. **정리할 폴더 경로**를 입력하고 **① 스캔** — 파일 목록과 완전 중복 파일이 즉시 표시됩니다 (해시 비교라 빠릅니다).
   **📋 스캔 결과** 탭에서 파일명/경로/AI 요약으로 검색하거나 확장자로 필터링할 수 있습니다.
4. **🗂️ 디렉토리 구조/연관도**, **🕸️ 파일 연관도** 탭에서 Obsidian 그래프 뷰 스타일로 폴더 계층과
   파일 간 관계를 바로 훑어볼 수 있습니다(AI 분석 전에는 파일명 유사도만, 분석 후에는 AI 요약까지 반영해 더 정확해집니다).
5. **② 분류 실행** — 조직 규칙으로 먼저 분류하고(신뢰도 '높음', AI 호출 없음), 규칙에 걸리지 않은
   파일만 요약해 AI에 보냅니다(비용 절감). Ollama가 꺼져 있으면 자동으로 규칙 기반만으로 진행됩니다.
   GPU 없는 PC에서는 AI 분석에 문단 하나당 약 40~80초가 걸릴 수 있으니, 시연 직전에 미리 한 번 돌려서
   캐시해 두는 것을 권장합니다 — 단, 캐시되는 건 파일별 요약뿐입니다. 요약을 묶어 폴더 구조를
   제안받는 단계(파일당 평균 약 26초, 아래 실측 참고)는 캐시되지 않으므로, "분류 실행"을 다시
   누르면 이 단계는 매번 새로 걸립니다.
   - **PC 사양에 맞는 모델 선택**: 이 PC에 설치된 Ollama 모델을 용량이 작은 순서로 드롭다운에서
     바로 고를 수 있습니다. 사양이 낮다면 가장 작은 모델을 고르거나, "AI 분류 사용" 체크를 꺼서
     AI 호출 없이 규칙 기반으로만 계속 쓸 수 있습니다(두 옵션 모두 즉시 다시 켤 수 있습니다).
   - **✂️ 이름 일괄 변경** 탭에서는 찾기/바꾸기·접두사/접미사·일련번호 규칙으로 여러 파일의
     이름을 한 번에 바꿀 수 있습니다(같은 폴더 내 이동으로 처리되어 이동 계획과 동일한 안전성
     검사·자동 복구·되돌리기가 그대로 적용됩니다).
   - 사이드바 **📐 폴더 구조만 복사** 에서는 파일 내용 없이 하위 폴더 체계만 다른 위치에 그대로
     만들 수 있습니다(새 프로젝트에 같은 폴더 뼈대를 재사용하고 싶을 때).
   - 사이드바 **🗂️ 조직 표준 템플릿** 에서 JSON 가져오기·현재 구조 활용 외에, 폴더 목록을
     한 줄씩 직접 입력해서 템플릿을 만들 수도 있습니다.
   - 같은 곳의 **"AI에게 구조 제안받기"**는 지금 스캔·요약된 파일 내용을 보고 AI가 새 구조를
     제안합니다. **완전 새 구조**(기존 템플릿에 얽매이지 않고 카테고리를 자유롭게 새로 지음) /
     **하이브리드**(현재 템플릿 폴더는 그대로 두고 부족한 카테고리만 추가) 두 방식 중 고를 수
     있고, "부서별로 나눠줘"처럼 원하는 방향을 한 줄로 알려줄 수도 있습니다. 파일이
     `DEFAULT_SUGGEST_BATCH_SIZE`(기본 15개)를 넘으면 자동으로 여러 번 나눠 호출해 결과를
     합치므로(진행률 표시), 대용량 폴더에서도 한 번의 AI 호출로 인한 타임아웃 없이 쓸 수
     있습니다. 제안은 표(카테고리·파일별 제안 위치·이유·신뢰도)로 먼저 보여주고, 마음에 안 들면
     **"🔁 그대로 다시" / "➖ 카테고리 더 적게" / "➕ 카테고리 더 많게"**로 힌트를 다시 입력하지
     않고도 바로 재시도할 수 있습니다. 검토 후 **"이 제안을 템플릿으로 저장"**을 눌러야만 실제
     템플릿이 됩니다 — "AI는 제안만, 사람이 최종 결정"이라는 원칙을 템플릿 생성 단계에도 그대로
     적용한 것입니다.
6. **📝 제안 편집** — 파일별로 추천 이유·신뢰도를 확인하고, 적용 여부를 끄거나 목적지를 직접 고쳐
   씁니다. 신뢰도/출처로 필터링하거나, 여러 파일을 한 번에 다른 폴더로 옮길 수 있습니다. 이 탭 하단에서
   실제 적용됐을 때의 **최종 상태**(이동/유지/제외/검토 필요/충돌 등)를 모두 볼 수 있고, JSON·엑셀
   리포트를 내려받을 수 있습니다.
7. **🚀 적용** 탭에서 최종 이동 계획을 다시 확인하고 동의 체크 후 적용하면 실제로 파일이 이동합니다.
   이 작업은 **🕘 버전 관리** 탭에 새 버전으로 기록되며, 더 최근 버전부터 순서대로 되돌릴 수 있습니다
   (더 최근 버전이 남아 있으면 과거 버전 되돌리기 버튼이 비활성화됩니다).

## 데모용 샘플 데이터

이름 규칙이 제각각인 문서와 완전 중복 파일을 포함한 "어질러진 폴더"를 부서별로 4가지 시나리오
중 골라 만들 수 있습니다. 웹 UI 홈 화면(또는 Streamlit 사이드바)의 **🧪 시연용 샘플 데이터**
카드에서 시나리오를 고르고 버튼 한 번으로 만들 수 있고, CLI로도 동일하게 만들 수 있습니다.
이미 존재하는 폴더는 `--force`를 붙이지 않으면 덮어쓰지 않습니다.

| 시나리오 키 | 부서 | 특징 |
|---|---|---|
| `general_office` (기본) | 총무·영업·마케팅 혼재 | 부서 구분 없는 전형적인 공유폴더. 34개 파일, 완전 중복 4개 |
| `dev_team` | 개발팀 | 기획/설계/API 문서, 배포·장애 대응, 스프린트 회의록. 22개 파일 |
| `ops_team` | 운영팀 | 서비스 운영 현황, 장애 포스트모템, 모니터링/SLA 리포트. 21개 파일 |
| `finance_team` | 회계팀 | 법인카드·경비 정산, 세금계산서, 급여, 결산 자료. 21개 파일 |

```bash
python sample_data/generate_sample_data.py                              # 기본(general_office)
python sample_data/generate_sample_data.py --dataset dev_team           # 개발팀 시나리오
python sample_data/generate_sample_data.py --dataset dev_team --force   # 다시 만들기(덮어쓰기)
```

각 부서 시나리오는 **같은 부서의 샘플 조직 템플릿**(아래)과 파일명이 맞춰져 있어, Ollama 없이
규칙 기반 분류만으로도 대부분(부서에 따라 62~100%) 자동으로 정리되는 것을 시연할 수 있습니다.

### 부서별 샘플 조직 템플릿

개발팀/운영팀/회계팀 표준 폴더 체계를 미리 만들어 뒀습니다. 조직 표준 템플릿 화면(웹 UI:
"조직 표준 템플릿" 메뉴, Streamlit: 사이드바 "🗂️ 조직 표준 템플릿")에서 카드를 클릭하면 바로
현재 템플릿으로 적용됩니다. 코드로는 `sample_data/org_templates.py`의 `SAMPLE_TEMPLATES`에서
확인할 수 있습니다.

## 프로젝트 구조

```
streamlit_app.py          # Streamlit UI (환경점검 -> 스캔 -> 규칙/AI 분류 -> 제안 편집 -> 적용) — 폴백
app/                       # 두 UI가 공유하는 핵심 백엔드 로직
  scanner.py               # 폴더 스캔, 해시 기반 완전 중복 탐지
  text_extractor.py         # .txt/.docx/.xlsx/.csv/.pptx/.pdf/.hwpx/.hwp 텍스트 추출
  llm_client.py             # Ollama 로컬 LLM 연동 (요약, 신뢰도/이유 포함 폴더 구조 제안 + 사용자 힌트/하이브리드 소프트 제약, 설치 모델 목록)
  templates.py              # 조직 표준 폴더 템플릿 + 규칙 기반 1차 분류 + AI 제안(자유/하이브리드) -> 템플릿 변환
  organizer.py              # 요약 오케스트레이션 + 캐싱, 규칙+AI 결합 분류, 템플릿 무관/하이브리드 구조 제안(배치 처리 + 재시도 조정), assignments 검증
  path_safety.py            # 목적지 경로 안전성 검증(대상 폴더 이탈/절대경로/예약어/충돌 차단)
  env_check.py              # 실행 환경 점검(Ollama/모델/권한/저장공간 등)
  structure_copy.py         # 파일 내용 없이 폴더 구조(뼈대)만 다른 위치에 복사
  rename_tool.py            # 파일명 일괄 변경 규칙(찾기/바꾸기, 접두/접미사, 일련번호)
  similar.py                # 유사 문서(버전 다른 파일) 탐지 (difflib 기반)
  relatedness.py            # similar.py/content_graph.py/directory_graph.py가 공유하는 유사도 점수 계산
  content_graph.py          # 파일 단위 연관도 그래프 (Obsidian 그래프 뷰 스타일)
  directory_graph.py        # 폴더 구조 트리 + 폴더 간 연관도 그래프
  search.py                 # 파일명/경로/AI 요약 검색 및 확장자 필터
  version_history.py        # 적용된 정리 작업의 버전 기록/되돌리기 관리(순서 어긴 복구 차단)
  file_ops.py               # 이동 계획 사전 저장, 즉시 로깅, 자동 롤백, 되돌리기(undo)
  report.py                 # 최종 상태 계산, Before/After 트리, JSON/엑셀/HTML 리포트
  plotting.py               # matplotlib 그래프용 한글 폰트 설정 유틸
api/                        # app/*.py를 감싸는 무상태 FastAPI 레이어 (Vue 프런트엔드용)
  main.py                   # 진입점 (uvicorn api.main:app)
  routers/                  # 도메인별 엔드포인트 (scan/classify/apply/versions/templates/sample-data 등)
  schemas.py, serialization.py
frontend/                   # Vite + Vue 3 + TypeScript + SCSS 웹 UI
  src/views/, src/stores/, src/components/, src/api/
sample_data/
  generate_sample_data.py   # 부서별(4종) 데모 샘플 폴더 생성 스크립트
  org_templates.py          # 부서별(개발팀/운영팀/회계팀) 샘플 조직 템플릿
tests/                      # pytest 단위 테스트 + API 테스트 + Streamlit AppTest 스모크 테스트 (Ollama 없이 실행 가능)
.github/workflows/tests.yml # PR/푸시마다 pytest를 자동 실행하는 CI
```

## 테스트

Ollama 연결이 필요 없는 핵심 로직(스캔, 경로 안전성, 이동/롤백/되돌리기, 규칙 기반 분류, 리포트 생성 등)은
단위 테스트로, 전체 화면 흐름(스캔 → 규칙 기반 분류 → 제안 편집 → 적용 미리보기)은
`streamlit.testing.v1.AppTest` 기반 스모크 테스트로 검증되어 있습니다. 모두 Ollama 없이 실행됩니다.

```bash
pip install -r requirements-dev.txt
pytest
```

PR과 푸시마다 GitHub Actions(`.github/workflows/tests.yml`)에서 동일한 테스트가 자동으로 실행됩니다.

## 알려진 제한사항

- 폴더 구조 제안은 로컬 소형 모델(`exaone3.5:2.4b`)이 생성하므로, 파일 수가 많거나 내용이
  복잡할 경우 제안 품질이 사람이 정리한 것만큼 정교하지 않을 수 있습니다. 최종 판단은 항상 사람이 하며,
  '📝 제안 편집' 탭에서 파일별로 직접 고칠 수 있습니다.
- `.hwp` 본문 추출은 OLE 레코드를 직접 파싱하는 방식(best-effort)이라, 표·필드 등 인라인 개체
  주변에 약간의 잡음이 섞이거나 일부 문서에서 파싱에 실패할 수 있습니다. 실패하면 자동으로 파일명·상위
  폴더 기준 임시 분류로 전환되며, 상태가 명확히 "파일명 기반 분류"로 표시됩니다.
- 완전 중복 파일 그룹에서 어떤 파일을 남기고 어떤 파일을 삭제할지는 자동으로 결정하지 않으며,
  중복 목록만 보여줍니다 (삭제는 범위 밖).
- 유사 문서 탐지 및 연관도 그래프는 임베딩 모델 없이 파일명·요약 문자열 유사도(`difflib`)로
  가볍게 판별하므로 완벽하지 않은 휴리스틱입니다.
- 연관도 그래프는 파일이 매우 많으면(400개 초과) 계산량이 급격히 늘어나 그리지 않고 안내 메시지만
  표시합니다. 데모 규모(30~50개)에서는 즉시 표시됩니다.
- 그래프 라벨은 한글 폰트(맑은 고딕/AppleGothic/나눔고딕 등)가 설치된 환경에서만 정상적으로
  표시됩니다. 하나도 없으면 한글이 네모(□)로 보일 수 있습니다.
- 조직 표준 템플릿은 현재 세션/로컬 캐시에 저장되며, 여러 사용자 간 공유는 JSON 파일을 내보내고
  가져오는 방식으로만 지원합니다(서버 동기화는 범위 밖).

  아니라 요약/캐시 결과만 저장됩니다.

  캐시·이력이 초기화됩니다.
